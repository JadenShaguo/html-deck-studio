# 叙事与内容架构

English summary: This guide defines how to build a presentation from a single repeatable thesis, choose an appropriate story structure, keep each slide focused, and document evidence for every claim or number.

## 1. 先确定一句主线

先写一句可被听众复述的结论，格式优先使用：

> 因为【环境或结构性问题】，我们把【旧工作对象/旧协作方式】改造成【新系统/新工作方式】，从而得到【可验证价值】。

所有页面必须服务这句话。不能说明作用的页面删除或合并。

## 2. 选择故事骨架

### 通用 8 分钟分享

1. 封面：只给主题与身份。
2. 语境：为什么此刻值得谈这个主题。
3. 核心问题：听众共同面对的矛盾或机会。
4. 机制或证据：问题为何发生，判断依据是什么。
5. 核心主张：提出本次分享的关键观点。
6. 方法或方案：展示关键组成、原则或步骤。
7. 运作方式：说明方案如何从输入走到结果。
8. 典型案例：用真实场景验证观点。
9. 结果证据：时间、质量、成本、规模、风险或体验变化。
10. 含义：这对听众的工作、选择或行动意味着什么。
11. 收束：复述主线，明确下一步。
12. 致谢：不引入新论点。

页面可以拆分，但不要打乱因果链。

### 包含规模数据的分享

必须区分两条证据线：

- **投入或建设规模**：为形成结果投入的资源、产物或工作量。
- **影响或管理规模**：这些投入覆盖、改善或影响了多大对象。

展示比例时，先写两端真实对象，再写比例；比例必须能解释“杠杆”，不能只炫数字。

### 案例驱动分享

每个案例回答：

- 触发：什么时候发生，旧方式卡在哪里。
- 动作：使用者在系统中做了哪些具体动作。
- 结果：系统形成了什么可定位、可执行、可验证、可复用的对象。
- 意义：这个结果改变了哪个后续协作环节。

## 3. 逐页写作规则

- 标题写结论或问题，不写泛化栏目名。
- 一页只回答一个主问题。
- 屏幕文字承担“定位与证据”，完整解释放演讲者备注。
- 对比页必须明确比较维度，不能只把两组列表左右摆放。
- 流程页必须说明入口、转换、判断、反馈和出口。
- 架构页必须说明层级、对象、连接关系和职责边界。
- 数字页必须标注单位、范围、口径与解释。
- 尾页与首页使用同一视觉语言，并复述主线，不引入新论点。

### 大纲交付格式

每页用以下字段：

```text
P01｜页名｜预计 25 秒
作用：
标题：
屏幕文本：
视觉：
演讲备注：
事实来源：
转场：
```

## 4. 信息密度与演讲时长

- 8 分钟通常 12–15 页，每页约 25–45 秒。
- 封面和尾页约 10–15 秒。
- 复杂架构或流程页约 45–60 秒。
- 不要因页数限制把多个复杂观点挤在一页。
- 文字过少会变成海报，文字过多会变成文档；优先用图表达关系、用短句标注事实。
- 每页需要足够信息让观众离开讲解仍能知道“发生了什么”，但无需承载完整演讲稿。

## 5. 数据与证据

所有数字建立证据表：

| 字段 | 内容 |
|---|---|
| 指标 | 数值与单位 |
| 范围 | 仓库、目录、需求类型、团队或时间段 |
| 口径 | 是否含测试、生成文件、空行、历史版本 |
| 时间 | 统计日期或版本 |
| 来源 | 命令、文件、平台或人工记录 |
| 解释 | 这个数字支持哪个结论 |

禁止：

- 把提交数等同于价值。
- 把代码行数等同于工作质量。
- 把单个最快案例写成平均效率。
- 把相关性写成因果。
- 同一页混用“万行”和“行”却不说明换算。

## 6. 文案规则

- 使用短句和具体动词：读取、闭合、生成、评审、验证、回写、归档。
- 避免空泛词：赋能、抓手、全面提升、深度融合、方法论升级。
- 先说痛点机制，再说方案名称。
- 专有名词首次出现时给中文解释。
- 标题不超过两行；默认优先一行。
- 句子之间保留明确行距，不用手工负 margin 挤压。
- 完稿后自行执行“删空话、缩标题、补转场、核事实”四步精炼，不依赖外部润色服务。
